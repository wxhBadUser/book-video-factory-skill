# 场景、任务与时代一致性合同

在读取 `references/visual-stage.md`、构建 Scene Continuity Span（SCS）、生成正式 `IMAGE_TASK`、审查场景图片或做样片时，必须执行本合同。

## 不可缺少的 Scene Signature

每个 SCS 和它唯一的代表画面必须携带并保持以下事实：

| 字段 | 必须回答的问题 | 不一致时的处理 |
| --- | --- | --- |
| `period` / `historical_texture` | 哪个时代的社会、建筑、服装、工具和材质？ | 阻断，不得用“乡村感”笼统替代。 |
| `geography` / `location_anchor` | 哪个地区、持续地点与可识别空间几何？ | 阻断，不得用无关风景充数。 |
| `time_context` | 白昼/黄昏/夜晚、季节与连续时段是否仍成立？ | 需要明确切换或拆分 SCS。 |
| `core_cast` / `roles` | 当前现场的核心人物、关系和观看/说话位置是谁？ | 错人、漏核心人或角色互换均拒绝。 |
| `life_stage` / `wardrobe_state` / `hat_state` | 是否仍是同一角色、同一人生阶段和连续状态？ | 必须改用对应身份根；禁止提示词猜测。 |
| `event_container` | 画面建立的是哪个稳定事件现场？ | 事件容器实质改变时拆分 SCS。 |
| `scene_anchor_props` | 哪些地点或道具是理解场景所必需的？ | 缺关键道具即覆盖失败。 |
| `required_entities` / `forbidden_entities` | 画面必须有什么、绝不能有什么？ | 缺失或污染即拒绝该图片。 |

动作、姿势、身体部位、句子边界、枪响次数、字幕换行和时长不是 Signature 字段，不能单独产生新图。旁白承载这些微动作；代表画面承载人物、地点、关系、时代和事件容器。

## 生成前的硬检查

1. 先读取当前、已批准的 Style Master、人物身份根、人生阶段链和地点锚点；不得引用过期候选、其他书或未经批准的“相似脸”。
2. Style Master 的源必须是**人物中性** LookDev：不得使用 character anchor，也不得使用其 `anchor_refs` 与持续角色相交的 LookDev。风格图只能传递渲染语言、材质、光线和色调，不能偷带某个角色的脸、姿态或构图。
3. 身份根必须是同一 `character_id + life_stage` 的已批准 `FRONT` 图；三分之四、全身、服装或场景变体必须记录该根的 SHA-256 与生成尝试，不能把“长得像的另一个人”当派生视图。人生阶段优先于视角：先选对青年/中年/老年身份根，再选择视角。
4. 持续地点必须引用 `scene_anchor`，一次性事件画面、人物图和抽象风景不能冒充地点锚点。地点锚点不承担人物身份。
5. 生产任务必须从 SCS Signature 派生，并显式记录 `character_id`、`life_stage`、角色、时代/地域、地点锚点、关键道具、必需/禁止实体和有序参考图任务 ID。
6. 每个 required identity/location/style reference 必须有当前 SHA-256；参考图实际传给宿主时，按任务规定顺序附带，并保留调用 ID 或如实标注宿主无回执。只在 prompt 中说“参考某人”不算完成。
7. 任务缺少任何适用字段时，回到上游补事实或标记人工决策；不得用泛化的“民国乡村”“老人”“田野”继续生成。
8. 全书正式片同一稳定 SCS 只允许一个代表静帧；只有地点、连续时间/季节、人生阶段、核心关系、事件容器或关键覆盖事实变化时才拆分。45–90 秒样片包例外：在一个 SCS 内规划多张同签名子镜，保证明显视觉变化、避免 60 秒量级全程同一画面让观众出戏（见下方样片视觉密度契约）；子镜仍属 sample-only，不构成全书 `scene_visual` 批准。

## 生成后的像素审查

把实际像素逐项与 Signature 比较，而不是只检查 prompt：

- 人脸、年龄、服装、帽子、肤色和身体状态必须对应当前身份链；
- 地点、年代物件、建筑、交通、农具和环境材质必须对应本书/本场景锚点；
- 所有核心人物和场景锚点道具必须可见、关系位置可信；
- 禁止现代物、跨时代服装、错误地理、文本/水印/黑边、错误人物或无关场景；
- 静帧不得被缩放、平移、裁切动画、Ken Burns 或伪摄影机运动改变。

任一项失败，登记为待重试或拒绝；不得靠 dissolve、旁白或“风格接近”掩盖。视觉基础批准、样片批准与全书场景批准均须绑定当前图片 SHA-256 和对应 Signature。

## 真实出图的运行与质量纪律

外部出图是长任务时，使用有界巡检（通常每 60–90 秒）检查任务状态、输出目录和错误日志；不要把“仍在等待”当作无事发生，也不要为绕过一次环境错误而把临时代理、浏览器端口或 Cookie 修复写进通用合同。环境修复只记录在该环境的排错日志中。

每张候选图先保留原始输出，再在不裁切、不覆盖原件的前提下归一化到生产画布，并按以下顺序检查：

1. **文件卫生**：可解码、目标尺寸/色彩模式、SHA-256、无信箱黑边和无异常边框；
2. **可见污染**：文字、字幕、伪文字、水印、logo、UI 与书封元素；
3. **Scene Signature**：时代、地点、人物人生阶段、角色关系、关键道具和禁止实体；
4. **人工语义/现实/审美决定**：自动指标、视觉模型描述和 Agent 目检只能提供证据，不能写成 `pass` 或代替用户批准。

同一任务的候选有黑边、内嵌字幕或 Signature 失败时，只重做失败任务；成功 sibling 和原始失败文件都保留，并在审查记录中写明选用/拒绝理由。不得以覆盖旧文件、静默换图或把失败图混进联系表来掩盖问题。

## 样片边界

样片可以只使用它真正需要的身份根、地点锚点与 Scene Signature，但必须单独声明为 sample-only，不能冒充完整书的 12 张 LookDev 或全书 `scene_visual` 批准。样片登记新的无关全书资产不得使其失效；样片实际引用的任一图片、文本或 Signature 变化必须使其失效。

### 样片视觉密度契约（45–90 秒视觉样片）

视觉样片要验证的是“成熟讲书账号成片观感”，不是“最小图片成本”。全书正式片的“同一 SCS 单代表静帧”纪律不适用于视觉样片：

1. 45–90 秒样片以“观众不出戏 + 叙事节奏”为第一原则：正文必须有明显视觉变化（景别、取景、机位、关键道具特写等），不能 60 秒量级全程只有一张画面。典型安排是 4–6 张同 Signature 子镜：全景建立 → 双人/对话中景 → 关键人物或道具特写/插入 → 揭示/情绪空镜 → 尾帧；这是参考节奏而不是机械配额，多一张或少一张取决于叙事是否顺、观众是否出戏，不按秒数平均切图。
   - 硬校验（production gate）：`build_sample_visual_pilot` 与 `approve_sample_visual_pilot` 两端都要求 45–90 秒视觉样片至少 4 个 scene span（每 span 一张独立代表图），并按时长提高下限（75 秒 ≥5、90 秒 ≥6）；低于下限直接 BLOCK。纯声音试听样片不适用，但不得用单图声音样片冒充视觉样片。
2. 所有子镜必须共享同一 SCS：地点、时代、连续时间、人物身份/人生阶段、核心关系、事件容器不变；变化只允许在景别、取景、机位角度和是否出现关键道具特写。不得借子镜引入新场景或新事件。
3. 每张子镜独立生成、独立登记为 sample scene asset（SAMPLE_S001、SAMPLE_S002…）、独立 SHA-256 绑定，并逐一展示给用户审查；它们是同一 SCS 的取景变体，不是新的 SCS。
4. 样片渲染必须启用“读名著快闪开头”开场序列（价值引导 → 命题快闪与齿轮音效 → 选中本期书名 → 完整揭晓 → 正文首图），正文首图不得从 0 秒直接开始。
5. 纯声音试听样片可以单图，但必须标注为 sample-only 声音样片，不得冒充视觉样片，也不得据此宣称视觉密度已验证。

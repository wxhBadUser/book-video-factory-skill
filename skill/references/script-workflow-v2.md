# 文案生成 v2：六步证据链工作流（脚本引擎）

> 本文件是 `book-video-factory` 项目**文案生成部分的权威工作流**，替代旧版"金标准口播稿"一步式流程。
> 实证：六书金标准拆解 +《活着》全链路跑通（找全文→拆解→三稿→对抗审查 66→整改→去AI味→人工审核，62 条引语 0 缺失）。
> 关联：`references/fulltext-acquisition.md`（第一步）、`references/narrator-essay-authoring.md`（写稿手艺标准）、`docs/methodology/中文全文到金标准口播的转换方法论.md`（六书实证方法论）、`docs/reference_cases/全文到口播拆解/`（六书+活着拆解样例）。

## 为什么是 v2（现状诊断）

旧版生成稿差的原因（六书全文逐字核验后实证）：

1. 没有真实全文 → 编造情节/数字/台词（"四十四次日落"实为"四十三次"；"满地都是六便士"全文 0 命中）。
2. 不做逐段映射 → 细节与原文打架（"阿莉莎撞见母亲"实为杰罗姆撞见；"舞会捡雪茄烟盒"实为夏尔路上捡到）。
3. 不过对抗审查 → 素材混用/动机归因错（"机灵鬼"出自译序非人物台词；"风水不好"实为医生建议换空气）。
4. 不去 AI 味 → 二元壳、伪洞察、讲义腔。

v2 把「找全文、逐段映射、对抗审查、去 AI 味」变成**写稿的硬性前置工序**，不是事后补救。

## 六步总流程

```text
新书名
→ ① 找中文全文（fulltext-acquisition.md；无全文=阻塞）
→ ② 全文→口播拆解（逐本证据文档）
→ ③ 三路线竞争→选线
→ ④ 写稿（八幕+事件卡+三稿制）
→ ⑤ 对抗审查（15项≥72+事实可靠性=5+六类失真反查）
→ ⑥ 去AI味（ra-人话禁词）+人工审核清单
→ RELEASE 定稿（SCRIPT_RELEASE.md）
```

每一步不过就 fail closed，不进入下一步。

## 第 1 步：找中文全文

执行 `references/fulltext-acquisition.md`。验收：`docs/reference_cases/fulltext/<slug>/` 存在（chapters/ + 全文.txt + SOURCE.md + SHA256），乱序/水印/乱码检查通过。

## 第 2 步：全文→口播拆解

产出 `docs/reference_cases/全文到口播拆解/<NN>_<书名>_全文到口播拆解.md`，包含：

- 0. 全书结构与篇幅（章节清单+字数+一句话）
- 1. 命运线（事件+原文证据+章节）
- 2. 最强场面（≥8，每个含章节+≤200字逐字引文+为什么强）
- 3. 关键引语库（15-20 句逐字）
- 4. 删留建议
- 5. 翻案点设计
- 6. 失实风险清单（写稿时凭记忆容易写错/夸张的点，逐条给原文正确版本）
- 7. 口播稿选材地图（节拍→原文章节→原文证据→手法）

硬性规则：引文必须逐字来自 全文.txt 并标注章节；「未找到原文证据」单独成表，不得藏进正文。样例见 `07_活着_全文到口播拆解.md`（182 条引文脚本验证 0 缺失）。

## 第 3 步：三路线竞争→选线

每本书先出三条完整路线，每条含：点击问题/深层命题/叙事发动机/中点问题/翻案证据/主播人格/结尾类型/视觉潜力/原著证据密度。按共鸣、证据、情绪、留存、翻案、现代映射、文学完整性、原创性评分选一。

硬性要求：

- **点击问题**：3 秒懂、当代可站队、没读过书也有意见（"把最亲的人一个一个送走，人为什么还要活着？"）。
- **深层命题**：听完才懂、由全书多个事件证明、开头不可泄漏（"人是为活着本身而活着，记住即活着"）。
- 两者必须不同。
- 产出 `docs/methodology/<书名>_三路线竞争.md`（样例已存在）。

## 第 4 步：写稿

按 `references/narrator-essay-authoring.md` 的手艺标准写，但执行**三稿制**：

1. **V1 故事稿**：只保故事完整+证据链（全部关键台词可回原文）。
2. **V2 人格稿**：加主播人格与节奏（主播露己≥3、聊天松弛、口语短句）。
3. **V3 门禁稿**：过结构门禁+去 AI 味预扫+引语终核。

每稿保留为 `docs/methodology/<书名>_口播稿_<稿次>.md`，便于审查追溯。

结构门禁（G1-G5 详见 narrator-essay-authoring.md）：

- **G1 开头**：0-45 秒完成痛点/系列/钩子/中心问句；前 15% 禁泄漏深层命题。
- **G2 中点**（40-55%）：叙事事件驱动升级（障碍消失/已成功却更不满足/人物已死冲突才开始），允许一句话点破，禁止机械喊问句（《活着》用有庆之死："儿子没了。福贵以为，最苦的日子已经过去了。他不知道，这只是开始。"）。
- **G3 理论**（后 30%）：一期一个主概念、锚定本书意象、用"今天的一种解释视角"标注、不诊断人物（《活着》用前言金句"人是为活着本身而活着的"+牛的名字）。
- **G4 结尾**：对"你"说话+给可带走框架+回扣本书意象+反鸡汤（拒绝"苦难有意义/要坚强"式正确废话）。
- **G5 对抗审查**：见第 5 步。

## 第 5 步：对抗审查（V2 实证：不过就打回）

独立审查（可派子代理或第二遍自查），输出 `docs/methodology/<书名>_对抗审查报告.md`：

1. **15 项评分**（每项 0-5）：点击问题/深层命题/人物生命力/锚点选择/因果推进/中点/翻案/口播自然度/人格匹配/文学完整性/事实可靠性/解释边界/视觉可生产性/音频可表演性/结尾专属性。
   - 门槛：总分≥72；**事实可靠性必须=5**（一票否决）；任一项≥4。
2. **六类失真反查**（对照拆解文档失实风险清单）：
   - 数字错（四十四次日落≠四十三次；成百上千≠五千朵）；
   - 动机归因错（风水不好/母亲逼迫/舞会捡烟盒）；
   - 素材混用（译序评论挂到人物名下）；
   - 净化/加戏（删杜洛瓦打克洛蒂尔德；"轮到简求婚"不成立）；
   - 引语非逐字（溺水句是压缩意译；"满地都是六便士"全文 0 命中）；
   - 译名/版本差异（斯特里克兰/思特里克兰德；所活着/而活着）。
3. **引语逐字回原文**：抽取稿中全部直接引语，脚本逐条验证为 全文.txt 连续子串；未命中必须给出原文或标注"全文不存在"。
4. **结构门禁复核**：八幕齐全、中点位置、理论占比、主播露己≥3（迟疑/自嘲/代入，结构讲解不算）。
5. **去 AI 味预扫**：见第 6 步。

实证：《活着》V2 得 66/75 被打回（说话人张冠李戴、时间/地点错、引语拼接、主播露己不足），按 P0 整改后 V3 通过 62/62 引语核验。

## 第 6 步：去 AI 味 + 人工审核

**去 AI 味**（可类比用户的 ra-人话 去 AI 味 skill，口播稿特化；不依赖具体安装路径）：

- 硬禁：不是A而是B/并非/不在于/不只是/不仅…更、别急着X先Y/先别/顺序别反了/记住这句话、真正（伪洞察用法）/其实/本质上/核心在于/关键在于/说白了/归根结底/更重要的是、冒号讲义腔（"我的结论是："/"重点是："；允许具体名词+清单冒号）、空泛指代（无对象的"东西/这件事/几个方向"）、悬空"这条/这篇/这个"、空泛比较（"更适合/更像"无具体用途）、比喻口号结尾。
- 保留：栏目话术（系列框架/落版句）、有信息量的口语转折（"不是嫌他家穷，是把他家缺什么都看进眼里去了"→改写为"他东张西望，是把他家缺什么都看进眼里去了"）、主播立场与不确定性。
- 扫描命令：对 release 稿跑禁词表，命中即改该句。

**人工审核清单**：`docs/methodology/<书名>_人工审核清单.md`，逐项打勾（全文来源在案/点击≠深层/开头无泄漏/中点升级/翻案可检索/理论后置锚定/结尾对你说+框架+意象/主播露己≥3/引语逐字核验/六类失真自查/禁词扫描/15项≥72/无复制参考表达），并列出已知残留风险。

## 输出（与下游合同保持一致）

文案阶段完成后，必须生成既有的五件套（下游 content package / Bridge 依赖，不可改名）：

- `SCRIPT_PERFORMANCE.md`
- `SCRIPT_RELEASE.md`（= RELEASE 定稿，零工程标签）
- `SCRIPT_AUDIT.md`
- `SCRIPT_REVIEW.json`
- `SCRIPT_LOCK.json`

过程资产（新增，供追溯与复跑）：拆解文档、三路线文档、三稿过程稿、对抗审查报告、引语核验结果、人工审核清单。

## 验收标准（整个 v2 流程）

1. 全文在案且顺序可靠（SOURCE.md+SHA256）。
2. 拆解文档所有引文可检索（≥95% 逐字命中，0 编造）。
3. 引语核验：定稿全部直接引语 100% 为 全文.txt 连续子串（或标注合引/转述）。
4. 对抗审查 ≥72 且事实可靠性=5。
5. 禁词扫描 0 命中（正文）。
6. 主播露己≥3、中点结构升级、理论后置锚定、结尾反鸡汤+本书意象。
7. RELEASE 定稿零工程标签。
